# Первый запуск AntiDDoS с пресетами безопасности

Шаблон: `deploy/config.security.example.json`. Все действия безопасно начинаются в
`dry_run`; CAPTCHA и nftables администратор включает только после калибровки.

## Установка

Для локальной сборки текущей ветки:

```bash
cd /www/antiddos
scripts/build-local.sh
sudo bash scripts/install.sh --local --web
```

Установщик сохраняет действующий `/etc/antiddos/config.json` при обновлении и
кладёт полный профиль в `/etc/antiddos/config.security.example.json`.

## Первый запуск профиля безопасности

1. Скопировать шаблон в `/etc/antiddos/config.json` и заменить пути логов на фактические.
2. Если SSH/UFW не подключены — оставить их правила `enabled:false`: демон не
   открывает источники, для которых нет включённых правил. Перед включением
   пресета указать существующий путь и выдать сервису права чтения.
3. Убедиться, что пользователь `antiddos` может читать файлы и проходить по их
   каталогам.
4. Проверить JSON и запустить сервис:

```bash
sudo jq . /etc/antiddos/config.json >/dev/null
sudo -u antiddos test -r /var/log/nginx/access.log
sudo systemctl restart antiddos
sudo journalctl -u antiddos -n 50 --no-pager
```

В UI администратор может включать пресеты, менять источник, regex, query_regex,
HTTP-статусы, окно, порог и действие. `cardinality` считает уникальные path либо
порты назначения, а не общее число событий.

## Что обнаруживают готовые паттерны

| Пресет | Сигнал атаки | Логика |
| --- | --- | --- |
| `web-sensitive` | Поиск `.env`, `.git`, `.aws`, `/proc/self`, `/etc/passwd` | Одного совпадения достаточно: обычное приложение не должно отдавать эти пути. |
| `web-home-burst` | Частые обращения к `/` | 10 запросов одного IP за 5 секунд. Выключен по умолчанию: порог зависит от трафика сайта. |
| `web-admin-probe` | Перебор `/admin`, `/login`, `wp-admin`, phpMyAdmin и похожих панелей | 10 запросов одного IP за минуту; отличает сканер путей от одиночной ошибки пользователя. |
| `web-sqli-query` | `UNION SELECT`, `OR 1=1`, `SLEEP()`, `BENCHMARK()` в query string | Сигнатурное правило, срабатывает сразу. Это базовый набор, а не полноценный WAF. |
| `nginx-basic-auth` | Ошибки Basic Auth (`password mismatch`) | 5 отказов одного IP за минуту из `nginx_error`. |
| `ssh-password` | Неуспешный пароль OpenSSH | 5 отказов одного IP за минуту из auth.log. |
| `ssh-invalid-user` | Подбор несуществующих SSH-пользователей | 3 разных события одного IP за минуту; порог ниже из-за более сильного сигнала разведки. |
| `port-scan` | Обращения одного IP к разным TCP/UDP-портам | 8 **уникальных портов** за 30 секунд из UFW/kernel netfilter log; повторы одного порта счётчик не увеличивают. |
| `web-unique-paths` | Быстрый обход большого количества URL | 30 **уникальных path** одного IP за 30 секунд; выключен до калибровки под сайт и поисковых роботов. |

User-Agent не считается доказательством легитимности: его можно подменить. Перед
включением CAPTCHA или nftables следует проверить реальные detection, добавить
доверенные мониторинги и прокси в whitelist и подобрать пороги под нормальный
трафик. Для CDN/reverse proxy в лог должен попадать реальный IP клиента.

Рекомендуемый порядок: 24–72 часа `dry_run`, настройка whitelist/порогов, затем
CAPTCHA для web-правил. nftables включать только для подтверждённых высокоточных
правил; сетевой ban действует на весь сервер, а не на один домен.
